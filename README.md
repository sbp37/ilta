# ILTA — 일타 · 할일 처치 RPG

할 일이 퀘스트가 되는 픽셀 RPG 투두 앱. 몬스터를 처치하고 세상을 밝히자.

**배포**: https://sbp37.github.io/ilta/ (GitHub Pages, `main` 푸시 시 자동 배포)

## 게임 규칙

- 할 일을 등록하면 난이도(잡몹/정예/보스)와 분류(공부·집안일·회사·건강·기타)에 따라 몬스터가 배정된다
- 처치하면 XP·골드·전리품을 얻고, 전리품은 모을수록 패시브 효과가 쌓인다
- 미루면(도망·마감 넘김·방치) 몬스터가 광폭화하고, 반복 설정(매일/평일/주 1회)도 가능
- 주간 보스 레이드 → 4주마다 챕터 보스(시즌제), 업적 20종, 펫·직업·장비·테마 수집
- 매일 "오늘의 일격" 지정, 하루 마무리 회고, 연속 처치 스트릭 + 휴식일 부적

## 개발

```bash
npm ci          # 의존성 설치 (Node 20+)
npm run dev     # 개발 서버 (Vite)
npm test        # 단위 테스트 (vitest)
npm run test:e2e # E2E 테스트 (Playwright, 브라우저 설치 필요: npx playwright install)
npm run lint    # ESLint
npm run format  # Prettier 전체 포맷
npm run build   # 타입체크 + 프로덕션 빌드
```

## 구조

- `src/game.ts` — 순수 게임 로직 (레벨·밸런스·분류·반복·챕터·업적 규칙)
- `src/store.ts` — `useGame()` 상태 훅 (localStorage 저장/마이그레이션 포함)
- `src/components/` — 화면 컴포넌트
- `public/sw.js` — 서비스 워커 (오프라인 캐시, PWA)
- `tests/` — vitest 단위 테스트 + `tests/e2e/` Playwright 스펙

데이터는 `localStorage`에 저장되며, 설정에서 JSON보내기/복원 가능.

## 일상 사용 흐름

- 이름 없이 시작할 수 있으며, 재방문하면 바로 퀘스트 화면이 열린다. 이름은 용사 꾸미기에서 변경한다.
- 수집함에서 검색·일정·분류·정렬로 작업을 찾고 바로 시작할 수 있다. PC에서는 퀘스트와 수집함을 함께 표시한다.
- 여러 개 정리에서 화면에 보이는 항목만 선택해 날짜·분류를 변경하거나 보관할 수 있다. 보관함에서는 진행 내용을 유지한 채 복원하며, 일괄 작업도 되돌릴 수 있다.
- 오늘 다시 고르기에서 오늘·수집함·내일·보관으로 계획을 재배치한다. 3일 이상 쉬고 돌아오면 선택적인 복귀 안내를 표시하고, 집중 중인 작업은 이동하지 않는다.
- 5분 시작과 일반 집중은 일시정지·재개·최소화를 지원한다. 집중 종료 후 사용자가 완료 여부를 정하며, 집중 기록과 완료 기록은 별도로 저장된다.
- 최소 목표와 권장 하루 목표(1~10개), 편안한 모험, 본문 글꼴, 움직임 줄이기를 설정할 수 있다. 최소 목표 달성은 별도의 중복 보상을 만들지 않는다. 기본 편안한 모험에서는 후퇴 횟수와 압박 표현을 표시하지 않는다.
- 모험일지의 첫 화면은 완료·회고이며, 통계와 수집은 별도 탭으로 제공한다. 내일의 일격 예약은 오늘의 일격을 보존한다.

## 저장과 복구

- 기존 저장 키와 v1/v2 마이그레이션을 유지하며, 정상 저장 직전의 데이터를 `ilta-save-backup`에 보관한다.
- 저장 실패 시 화면의 기록을 유지하고 내보내기를 제공한다. 손상된 저장은 자동 백업으로 읽되 확인 전 원본을 덮어쓰지 않는다.
- 다른 창의 저장 변경을 감지하면 자동 저장을 중단한다. 현재 기록을 내보낸 후 최신 내용을 열어 충돌을 해소한다.
- 완료/삭제 되돌리기는 해당 행동만 취소한다. 그 뒤의 신규 작업은 보존하며, 보상 사용 등 종속 변경이 있으면 취소를 막는다.
- 계정 기반 기기 동기화와 앱이 닫힌 상태의 예약 알림은 아직 지원하지 않는다.
- 배포 빌드에서 앱 파일 전체와 폰트·아이콘의 사전 캐시 목록을 생성한다. 첫 설치가 완료되면 오프라인 재실행이 가능하고, 캐시 정리는 일타의 캐시만 대상으로 한다. 브라우저 저장 자체를 지우면 로컬 자동 백업도 함께 사라지므로 중요한 기록은 JSON 파일로 별도 보관해야 한다.
