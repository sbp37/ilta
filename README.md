# ILTA — 일타 · 할일 처치 RPG

할 일이 퀘스트가 되는 픽셀 RPG 투두 앱. 몬스터를 처치하고 세상을 밝히자.

**배포**: https://sbp37.github.io/ilta/ (GitHub Pages, `main` 푸시 시 자동 배포)

## 게임 규칙

- 할 일을 등록하면 난이도(잡몹/정예/보스)와 분류(공부·집안일·회사·건강·기타)에 따라 몬스터가 배정된다
- 처치하면 XP·골드·전리품을 얻고, 전리품은 모을수록 패시브 효과가 쌓인다
- 미루면(도망·마감 넘김·방치) 몬스터가 광폭화하고, 반복 설정(매일/평일/주 1회)도 가능
- 주간 보스 레이드 → 4주마다 챕터 보스(시즌제), 업적 20종, 펫·직업·장비·테마 수집
- 매일 "오늘의 일격" 지정, 하루 마무리 회고, 연속 처치 스트릭 + 휴식일 부적
- 주민 6명이 분류·제목에 맞는 의뢰를 맡고, 처치한 기록으로 각자의 공간이 자란다. 몬스터·주간 보스·기존 보상은 그대로 유지한다.

## 주민과 작은 마을

- 공부는 사서 모아, 업무는 대장장이 두리, 건강은 약초사 초롱, 집안일은 여관 주인 보리, 창작·취미는 음유시인 라라, 그 밖의 일은 우편배달부 루루가 맡는다.
- 직접 고른 분류가 우선이다. 분류가 없거나 기타이면 제목의 로컬 규칙으로 추정한다. 외부 API 전송이나 추가 선택 없이 연결하며, 사용자가 입력한 제목은 바꾸지 않는다.
- 퀘스트에는 담당 주민과 짧은 대사가 표시된다. 완료 한 번으로 기존 보상·보스 피해·마을 성장이 함께 반영되며, 별도 수확이나 호감도 관리가 없다.
- 퀘스트의 `마을 산책` 또는 모험일지의 `마을`에서 주민을 만나고 최근에 도와준 일을 볼 수 있다. 주민별 완료 0/1/5/15개에 캠프/보금자리/가게/꽃 핀 거리로 바뀐다.
- 주간·챕터 보스 격퇴 수는 광장의 왕관과 깃발로 남는다. 쉬거나 보스를 잡지 못해도 마을은 쇠퇴하지 않는다.
- 성장은 기존 완료 이력과 보스 격퇴 수에서 계산한다. 기존 기록도 반영되고, 새로고침·파일 복원·완료 되돌리기에 함께 적용된다. 저장 스키마나 경제 밸런스는 변경하지 않는다.

## 개발

```bash
npm ci          # 의존성 설치 (Node 20+)
npm run dev     # 개발 서버 (Vite)
npm test        # 단위 테스트 (vitest)
npm run test:e2e # E2E 테스트 (Playwright, 브라우저 설치 필요: npx playwright install)
npm run lint    # ESLint
npm run format  # Prettier 전체 포맷
npm run build   # 타입체크 + 프로덕션 빌드
```

## 구조

- `src/game.ts` — 순수 게임 로직 (레벨·밸런스·분류·반복·챕터·업적 규칙)
- `src/store.ts` — `useGame()` 상태 훅 (localStorage 저장/마이그레이션 포함)
- `src/village.ts` / `src/villageSprites.ts` — 주민 배정·대사·성장 규칙과 도트 자산
- `src/components/` — 화면 컴포넌트
- `public/sw.js` — 서비스 워커 (오프라인 캐시, PWA)
- `tests/` — vitest 단위 테스트 + `tests/e2e/` Playwright 스펙

데이터는 `localStorage`에 저장되며, 설정에서 JSON보내기/복원 가능.

## 일상 사용 흐름

- 화면은 차분한 바탕과 얇은 구분선을 사용하고, 버튼·메뉴에는 각진 테두리와 작은 입체감을 둔다. 픽셀 메뉴 아이콘과 캠프 장면을 유지하며, 반복 움직임은 캠프 장면에만 제한한다. 화면 줄무늬와 강한 빨간 전체 테두리는 사용하지 않는다.
- 모험 정보와 보스 상세는 눌러 펼친다. 수집함의 분류·난이도, 필터·정렬도 접힌 상태로 시작하며 선택된 조건은 요약에 표시한다. 상점은 내 보상·장비·소모품 탭으로 나눈다.
- 이름 없이 시작할 수 있으며, 재방문하면 바로 퀘스트 화면이 열린다. 이름은 용사 꾸미기에서 변경한다.
- 오늘 할 일은 보스 정보보다 먼저 표시하며, 입력칸 하나에서 연속 등록한다. 다른 곳을 누르는 것만으로 등록하지 않고 추가·취소로 결정한다. 슬롯이 가득 차면 새 입력은 수집함에 보관한다.
- 오늘·수집함의 작성 중 제목과 수집함의 분류·난이도는 탭 이동 중 유지된다. 아직 등록하지 않은 초안은 새로고침하거나 앱을 닫으면 사라진다.
- 수집함의 상세 입력에서 마감·반복·작은 단계를 함께 등록한다. 단계 이름 수정·삭제와 작업 수정 되돌리기를 지원하며, 기존 체크와 보상 이력을 보존한다. 편집창을 닫을 때 미저장 변경을 확인한다.
- 수집함에서 검색·일정·분류·정렬로 작업을 찾고 바로 시작할 수 있다. PC에서는 퀘스트와 수집함을 함께 표시한다.
- 여러 개 정리에서 화면에 보이는 항목만 선택해 날짜·분류를 변경하거나 보관할 수 있다. 보관함에서는 진행 내용을 유지한 채 복원하며, 일괄 작업도 되돌릴 수 있다.
- 오늘 다시 고르기에서 오늘·수집함·내일·보관으로 계획을 재배치한다. 3일 이상 쉬고 돌아오면 선택적인 복귀 안내를 표시하고, 집중 중인 작업은 이동하지 않는다.
- 5분 시작과 일반 집중은 일시정지·재개·최소화를 지원한다. 집중 종료 후 사용자가 완료 여부를 정하며, 집중 기록과 완료 기록은 별도로 저장된다.
- 집중 중인 작업을 카드의 나중에 하기/후퇴로 옮겨도 이미 집중한 시간은 한 번 기록한다.
- 최소 목표와 권장 하루 목표(1~10개), 편안한 모험, 본문 글꼴, 움직임 줄이기를 설정할 수 있다. 최소 목표 달성은 별도의 중복 보상을 만들지 않는다. 기본 편안한 모험에서는 후퇴 횟수와 압박 표현을 표시하지 않는다.
- 모험일지의 첫 화면은 완료·회고이며, 통계와 수집은 별도 탭으로 제공한다. 내일의 일격 예약은 오늘의 일격을 보존한다.
- 완료·집중·회고는 날짜별로 함께 표시한다. 전체 이력에서 검색하고 종류, 오늘/최근 7일/30일/직접 지정 기간으로 좁힐 수 있다. 한 번에 40개씩 표시하며 예전 집중 기록도 검색 대상에 포함한다.

## 저장과 복구

- 기존 저장 키와 v1/v2 마이그레이션을 유지하며, 정상 저장 직전의 데이터를 `ilta-save-backup`에 보관한다.
- 설정의 저장·복구 탭에서 날짜별 자동 백업 최대 6개와 복구 직전 기록 최대 2개를 확인한다. 이력은 `ilta-save-history`에 저장하며 용량 제한 또는 브라우저 여유 공간에 따라 오래된 이력부터 줄인다. 일반 저장은 백업 저장 실패 때문에 중단하지 않는다.
- 파일과 백업은 이름·할 일·보관·완료·레벨을 현재 기록과 비교한 뒤 복구한다. 손상된 할 일의 제외는 별도 확인을 받고, 미래 버전 파일은 거부한다. 복구 전 기록의 백업과 실제 저장이 성공해야 화면을 교체하며 진행 중 타이머는 종료한다. 미리보기 이후 저장 변경이 감지되면 재선택을 요구한다.
- 저장 실패 시 화면의 기록을 유지하고 내보내기를 제공한다. 손상된 저장은 자동 백업으로 읽되 확인 전 원본을 덮어쓰지 않는다.
- 다른 창의 저장 변경을 감지하면 자동 저장을 중단한다. 현재 기록을 내보낸 후 최신 내용을 열어 충돌을 해소한다.
- 완료/삭제/수정 되돌리기는 해당 행동만 취소한다. 그 뒤의 신규 작업은 보존하며, 보상 사용 등 종속 변경이 있으면 취소를 막는다.
- 계정 기반 기기 동기화와 앱이 닫힌 상태의 예약 알림은 아직 지원하지 않는다.
- 배포 빌드에서 앱 파일 전체와 폰트·아이콘의 사전 캐시 목록을 생성한다. 첫 설치가 완료되면 오프라인 재실행이 가능하고, 캐시 정리는 일타의 캐시만 대상으로 한다. 브라우저 저장 자체를 지우면 로컬 자동 백업도 함께 사라지므로 중요한 기록은 JSON 파일로 별도 보관해야 한다.
